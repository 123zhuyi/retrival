## Scheduling Optimization: dynamic autotuning

【优化维度】：多核并行与负载均衡
【泛化层级】：条件性（迁移条件：硬件 910b2, 910b3, 91093, 91095；失效边界：M/N/K < 128 的小 shape 上调优空间小，autotune 开销可能抵消收益；依赖调优配置表覆盖目标 shape，未覆盖的 shape 退化为默认配置；do_not_specialize 不适用于影响控制流或边界判断的标量参数）

### 原则
- **dynamic autotuning**：The kernel leverages `runtime.get_tuned_config("addmm")` to dynamically select the optimal tile sizes (blockM, blockN, blockK) based on the runtime dimensions of M, N, and K. This allows the kernel to adapt to different matrix shapes, maximizing hardware utilization compared to static tiling.
- **strict precision control**：The `tl.dot` operation is explicitly configured with `allow_tf32=False`. This ensures that the computation maintains high numerical precision by avoiding reduced-precision TensorFloat-32 formats, which is crucial for training stability and models sensitive to accumulation errors.
- **stride agnostic memory access**：The kernel calculates memory pointers using stride arguments (`stride_am`, `stride_ak`, etc.) rather than assuming contiguous memory. This allows the kernel to operate directly on transposed matrices or sliced tensors without requiring an explicit layout transformation (transpose/permute) prior to the kernel launch, saving memory bandwidth.
- **compilation optimization**：The `do_not_specialize` attribute is applied to scalar arguments `alpha` and `beta`. This prevents the JIT compiler from generating a unique kernel version for every distinct scalar value, significantly reducing compilation overhead and binary size while maintaining execution speed.

### 代码/骨架出处
- `TritonPath`:
```python
raw_experiences/extracted_kernels/119-addmm_kernel.py
```

**坏实践（反例）**：为 matmul 类 kernel 写死单一 tile 配置（如 BLOCK_M=BLOCK_N=BLOCK_K=128）覆盖所有 shape → 狭长 shape（小 M 大 N 或大 M 小 N）上 AICore 利用率不足，大 shape 上 tile 又可能超出 UB 预算导致 spill → ✅ 正解即本条：按运行时 M/N/K 动态选择 tile 配置。

**已知实例**：matmul §raw (`experiences/matmul/exp_addmm_ascend_001.yaml`)
- 声称性能收益：25%
- 备注：The kernel utilizes `tle` (Triton Language Extensions) and `@libentry()`, indicating it is specifically optimized for the Ascend NPU architecture (910 series) via the Torch-NPU/Triton integration.
