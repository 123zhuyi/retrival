## Scheduling Optimization: persistent kernel grid stride

【优化维度】：多核并行与负载均衡
【泛化层级】：条件性（迁移条件：硬件 910b2, 910b3, 91093, 91095；失效边界：total_tiles 不大于物理核数时 grid-stride 无摊薄收益；原子加竞争随 token 分布集中而加剧；显式指针算术的收益依赖编译器别名分析，对完全动态 stride 的场景不确定）

### 原则
- **persistent kernel grid stride**：The kernel implements a grid-stride loop strategy using `for pid in range(pid0, total_tiles, num_aicores)`. This maps a potentially large number of logical tiles to a fixed number of physical AICores, significantly reducing kernel launch overhead and scheduling latency compared to a 1:1 grid mapping.
- **compiler friendly pointer arithmetic**：In the backward pass accumulation loop, the code calculates the absolute memory address explicitly (`base + offset + k * stride`) inside the load operation rather than incrementing a pointer variable across iterations. This specific pattern assists the compiler in performing alias analysis and inferring contiguous memory access patterns, leading to more efficient load instructions.
- **atomic gradient accumulation**：Utilizes `tl.atomic_add` to handle concurrent writes to the `d_weight` matrix. This resolves race conditions where multiple thread blocks (processing different tokens) update the same weight parameters, which is essential for the correctness of the backward pass.
- **grouped gemm scheduling**：Employs `GROUP_SIZE_M` to process multiple M-dimension blocks together. This improves data locality and allows for better reuse of loaded weight tiles across the grouped blocks.

- `TritonPath`:

**坏实践（反例）**：多个 program 并发写同一权重梯度区域却不用原子操作（或另起归约 kernel + 中间 buffer）→ 竞态写丢更新 / 额外 launch 与显存开销 → ✅ 正解即本条：`tl.atomic_add` 内核内归约 + 显式 `base + offset + k*stride` 指针表达式辅助编译器向量化。

**已知实例**：loss §raw (`experiences/loss/exp_entropy_backward_d_weight_001.yaml`)
- 声称性能收益：25%
- 备注：This kernel is specifically optimized for the Ascend 910 series architecture. It reconstructs logits during the backward pass, requiring high memory bandwidth and compute density. The pointer arithmetic optimization is critical for achieving peak load efficiency on the NPU.
