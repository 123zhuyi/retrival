## Compute Optimization: two pass algorithm

【优化维度】：AICore 单元利用/Scalar 削减
【泛化层级】：条件性（迁移条件：硬件 910b2, 910b3；失效边界：dW 部分和需 kernel 外再做一次归约（备注自述），行数小时该额外 pass 占比升高；n_cols < 1024 时两遍结构可简化；原子免费的 pid 分片缓冲需要额外的临时显存）

### 原则
- **two pass algorithm**：The kernel separates the computation into two distinct passes over the data. The first pass calculates the reduction term (sum(m * X)) required for the RMSNorm correction factor. The second pass applies this factor to compute the final gradients dX and dW. This approach avoids the complexity of materializing the entire intermediate row state in limited local memory.
- **grid stride scheduling**：Implements a grid-stride loop (using tl.range with a step equal to num_progs) to allow a single program instance to process multiple rows. This ensures high utilization of the NPU cores by balancing the workload when the number of rows is small or not evenly divisible by the grid size.
- **atomic free dW accumulation**：Instead of performing atomic additions to the global dW tensor, which causes severe contention, each program instance accumulates its partial dW results into a unique slice of a temporary buffer indexed by the program ID (pid). This eliminates synchronization overhead and write conflicts during the main computation loop.
- **mixed precision strategy**：Supports specific casting modes where inputs are explicitly cast to fp32 before accumulation. This ensures that the reduction operations maintain sufficient numerical precision, preventing overflow or underflow that can occur with fp16/bf16 accumulation during the backward pass.

### 代码/骨架出处
- `TritonPath`:
```python
raw_experiences/extracted_kernels/095-_fused_add_rms_norm_backward_kernel_npu.py
```

**坏实践（反例）**：各 program 对全局 dW 直接 `atomic_add` → 权重梯度的原子写严重竞争 → ✅ 正解即本条：每个 program 写入按 pid 索引的独立临时分片（原子免费），kernel 外再做一次归约。

**已知实例**：normalization §raw (`experiences/normalization/exp_rmsnorm_backward_npu_001.yaml`)
- 声称性能收益：25%
- 备注：The dW output generated by this kernel consists of partial sums per program ID. A final reduction step over the program dimension is required outside the kernel to obtain the final weight gradients.
