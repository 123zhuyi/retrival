# 101_SlaFwd 性能优化报告

## 结论

| 指标 | 值 |
|---|---|
| verify（`scripts/verify.py`） | **50/50** |
| benchmark 采集 | **50/50** |
| framework 平均时延（几何平均） | 121.48 ms |
| implementation 平均时延（几何平均） | 18.8983 ms |
| **speedup_vs_torch（新口径 `triton_dev_v2`）** | **6.43x** |
| speedup（旧口径，同一份代码） | 0.0237 |
| 单 case 区间 | 0.72 ~ 22.1 |

目标 ≥2.0x，实际 **6.43x**。

⚠️ **两套口径差 400 倍**：旧版 `benchmark.py` 把"同名 kernel 一次 forward 内发射 L 次"
低估为 1/L，而本算子的参考实现是 B×H×MQ 三重 Python 循环、单次 forward 发射几百个 kernel，
于是分子被严重低估（旧口径 framework 0.4418 ms → 新口径 121.48 ms）。
impl 侧代码一字未改。**报数前必须先确认 benchmark.py 的版本。**

## 交付基线的问题

历史交付的 `101_SlaFwd_generated.py` **几乎全是 torch**（只有一个 combine_kernel），
而且**过不了 AST 退化预检**（helper 里有 `torch.softmax` / `.matmul`，命中 Type 3）——
它本身就不是合法交付物。本轮从零写了 6 个 Triton kernel 的完整实现。

## 实现结构（6 个 kernel）

| kernel | 职责 |
|---|---|
| `sla_stats_kernel` | 一次扫 k/v，同时出 `k_mean`、`kvsum = c_kᵀ@v`、`ksum`（线性分支的全局量） |
| `sla_bmean_kernel` | `qm` / `km` 的块均值（km 先减 `k_mean` 的 dtype 版本） |
| `sla_pooled_kernel` | `pooled = qm @ kmᵀ`，**必须 round 回 dtype 再给 topk 用**（参考就是这么做的） |
| `sla_topk_kernel` | 位序 int32 key + 阈值二分选块 |
| `sla_attn_kernel` | 块稀疏 FlashAttention → `o_s` |
| `sla_linear_kernel` | 线性分支 `o_l` + 合并 + `@W_lᵀ` |

## 精度上两个必须逐位对齐的点

1. **`aclnnTopk` 并列时取小索引。** 17 个 case 逐个比对：
   「值降序、并列取小索引」0 处不一致；「取大索引」8 个 case 有 1~12 行不一致。
2. **`-0.0` 必须归一到 `+0.0`。** 位序 key 把 `-0.0` 排在 `+0.0` 之前，而 `torch.topk`
   认为两者相等。pooled 里 fp32 的极小负值 round 到低精度就会变成 `-0.0`。
   CPU 穷举 3120 组随机行（651 组含 `-0.0`）：不修 179 组不一致，修完 0 组。

选块是**离散**的：差一个块 = 整行结果不同，表现为 `matched_ratio` 断崖，
不是缓慢劣化 —— 这类算子必须先验证选块集合，再看数值精度。

### ★ 关键实测：`tl.cumsum` 在 Ascend 上极慢

同一 kernel 形状（`[11392, 2048]`）对照：

| 版本 | 耗时 |
|---|---|
| 带一次 `tl.cumsum` | **14.33 ms** |
| 去掉 cumsum（其余不变） | **0.254 ms** |

**56×**。而且慢到会触发 **Vector core 看门狗**（`507035 / vector core execution is abnormal`），
在正式 benchmark 里表现为跑到某个 case 直接崩。

**分层 cumsum 无效**（已证伪）：把 `[BR, NP2]` 拆成 `[BR, NCH, CH]` 两级，
CH=64/128/256 实测 15.8 / 15.1 / 14.7 ms，**全部不比扁平的 14.3 ms 快**
⇒ 代价与"参与前缀和的元素总数"成正比，不是与轴长成正比，拆轴没有意义。

**正解（已写进 template §4.3）：把前缀和写成矩阵乘丢给 Cube**

```python
# inclusive_prefix(x)[i] = Σ_{j<=i} x[j] = (x @ U)[i],  U[j,i] = 1 if j <= i
U = (c[:, None] <= c[None, :]).to(tl.float16)   # CH<=128，计数值在 fp16 里精确
inner = tl.dot(x, U)                            # 块内前缀：一次 Cube 乘法
tot   = tl.sum(x, 1)
pre   = tl.sum(tl.where(a[:, None] > a[None, :], tot[None, :], 0.0), 1)   # 块间前缀
pos   = inner + pre[:, None]
```
该写法已单独验证正确（300 元素随机 0/1 与 `torch.cumsum` 逐位一致）。
**未并入交付版本**：接进 topk 后出现"每行少选 1 个块"的偏差（见迭代日志的证伪记录），
在 budget 内没有定位完，交付版本仍用 cumsum 版（verify 50/50、benchmark 50/50）。
