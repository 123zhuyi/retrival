## Compute Optimization: tiling strategy

【优化维度】：AICore 单元利用/Scalar 削减
【泛化层级】：条件性（迁移条件：硬件 910b2, 910b3, 91093, 91095；失效边界：BLOCK_K 超出片上 SRAM/L1 容量时 tile 无法驻留、引入 spill；D_qk < 64 时整段可一次装入，无需分块；假设输入 layout 适配向量化 load（如 NC1HWC0），layout 不匹配时需先做变换）

### 原则
- **tiling strategy**：The kernel implements a blocking strategy on the reduction dimension (D_qk) using the blockK parameter. By iterating over the D_qk dimension in chunks, it loads sub-blocks of inputA and inputB into on-chip memory (SRAM/L1), maximizing data reuse per global memory access and significantly reducing memory bandwidth pressure.
- **hardware acceleration**：Utilizes the tl.dot intrinsic for the core computation (l1_q @ l1_k.trans). This maps directly to the hardware's dedicated matrix multiplication units (e.g., Ascend Cube Unit or NVIDIA Tensor Core), providing substantially higher throughput compared to standard FMA instructions.
- **precision management**：The accumulator qk_acc is explicitly initialized to tl.float32. This mixed-precision approach allows for high-speed computation with lower precision inputs (fp16/bf16) while maintaining numerical stability during the reduction phase, which is critical for attention mechanisms.
- **boundary handling**：Employs dynamic masking (mask=mask_D) during the load operations to safely handle cases where the head dimension (D_qk) is not an exact multiple of the block size (blockK). This ensures correctness without the overhead of padding the input tensors.

### 代码/骨架出处
- `TritonPath`:
```python
cube1
```

**坏实践（反例）**：fp16/bf16 输入直接累加进同精度 accumulator → 长归约链上误差持续累积，score 数值漂移 → ✅ 正解即本条：累加器显式 fp32（`qk_acc = tl.zeros(..., tl.float32)`），仅输入保持低精度喂给矩阵单元。

**已知实例**：matmul §raw (`experiences/matmul/exp_cube1_qk_gemm_001.yaml`)
- 声称性能收益：35%
- 备注：This kernel is optimized for the score 投影（inputA·inputB^T）phase of attention-like mechanisms. It assumes inputs are in a memory layout conducive to vectorized loading (likely NC1HWC0 or similar NPU-friendly formats).
