## Compute Optimization: two pass algorithm

【优化维度】：AICore 单元利用/Scalar 削减
【泛化层级】：条件性（迁移条件：硬件 910b2, 910b3；失效边界：两遍实现重读 out_grad（备注自述），内存 Bound 场景应考虑缓存或融合；M < 128 时块配置需重调；scale 归约必须 fp32，低精度累加在 softmax 导数上误差敏感）

### 原则
- **two pass algorithm**：The kernel separates the computation into two distinct passes a reduction pass to calculate the sum of gradients (scale) and a computation pass to derive the input gradients. This decouples the global reduction dependency from the element-wise calculation.
- **block tiling**：Utilizes 2D tiling with blockM and blockN to process data in chunks. This allows for vectorized memory loads and stores, significantly improving memory bandwidth utilization compared to element-wise processing.
- **high precision accumulation**：The reduction variable 'scale' is explicitly initialized and computed using tl.float32. This ensures numerical stability during the summation of gradients, preventing overflow or underflow which is critical for softmax derivative calculations.
- **mask loading**：Implements boundary checks using masks during memory loads and stores. This ensures the kernel operates correctly even when the matrix dimensions (M, N) are not perfectly divisible by the block sizes.

### 代码/骨架出处
- `TritonPath`:
```python
raw_experiences/extracted_kernels/145-log_softmax_backward_kernel.py
```

**坏实践（反例）**：梯度求和（scale）直接用输入精度归约 → softmax 导数的长链求和上溢/下溢 → ✅ 正解即本条：scale 用 `tl.float32` 归约 + blockM/blockN 二维分块 + mask 处理不整除（备注已知改进点：out_grad 两遍读取可在寄存器允许时融合消除）。

**已知实例**：softmax §raw (`experiences/softmax/exp_log_softmax_backward_001.yaml`)
- 声称性能收益：25%
- 备注：The current implementation loads 'out_grad' twice (once for reduction, once for calculation). While this improves readability and reduces register pressure, it increases memory traffic. For memory-bound scenarios, consider caching 'out_grad' in software-managed cache (SRAM) if available or fusing the loops if register file permits.
