## Scheduling Optimization: diagonal partitioning

【优化维度】：多核并行与负载均衡
【泛化层级】：条件性（迁移条件：硬件 910b2, 910b3；失效边界：对角划分仅在 M、N 方向都 ≥ 8 个块时触发，否则回退顺序划分（备注自述）；NUM_CORES=24 硬编码绑定具体芯片，换芯片需改；M 固定 32 的 autotune 空间只适合瘦长矩阵）

### 原则
- **diagonal partitioning**：Implements a diagonal block distribution strategy using LCM calculations when grid dimensions exceed BLOCK_THRESHOLD. This optimizes memory access patterns and reduces bank conflicts compared to standard row-major traversal.
- **hardware specific hint**：Utilizes `tl.compile_hint(..., "dot_pad_only_k")` to instruct the backend compiler to pad only the K dimension for the dot product operation, aligning with the Ascend Cube unit's requirements for efficient computation.
- **multi core scheduling**：Explicitly distributes workload across 24 AI cores (`NUM_CORES 24`) using a strided loop, ensuring full utilization of the hardware's compute resources.
- **autotuning strategy**：Employs `@triton.autotune` to search over optimal tile sizes for N and K dimensions while keeping M fixed at 32, adapting to varying matrix shapes.

### 代码/骨架出处
- `TritonPath`:
```python
raw_experiences/extracted_kernels/031-matmul_kernel.py
```

**坏实践（反例）**：大网格按行优先遍历 + 对整个 tile 全维 padding → bank 冲突 + M/N 维冗余搬运 → ✅ 正解即本条：LCM 对角块分布 + `dot_pad_only_k` 只 pad K 维 + 24 核跨步调度。

**已知实例**：matmul §raw (`experiences/matmul/exp_matmul_ascend_diag_001.yaml`)
- 声称性能收益：25%
- 备注：The diagonal partitioning logic is triggered only when both M and N dimensions are sufficiently large (>= 8 blocks). Otherwise, it falls back to sequential partitioning.
