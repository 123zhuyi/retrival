## Scheduling Optimization: dynamic work stealing

【优化维度】：多核并行与负载均衡
【泛化层级】：条件性（迁移条件：硬件 910b2, 910b3；失效边界：各组维度差异小时动态调度相对静态分配无优势（备注自述：差异大时最有效）；依赖 `dl.compile_hint` 硬件提示，非 Ascend 环境不可用；while 式动态调度有额外的计数/分支开销，组内维度小且均匀时不划算）

### 原则
- **dynamic work stealing**：The kernel implements a dynamic scheduling strategy within the group loop. By calculating `cur_block` based on `core_idx` and `total_cores` and iterating with a `while` loop, it ensures that all compute cores are utilized efficiently even when different groups have vastly different K dimensions (computational loads). This mitigates the "tail effect" common in static scheduling of grouped operations.
- **hardware specific padding hint**：The use of `dl.compile_hint(..., "dot_pad_only_k")` is a critical hardware adaptation for Ascend NPUs. It instructs the compiler to pad only the K dimension of the tiles to align with the hardware's matrix multiplication unit (Cube) requirements, rather than padding the entire block. This significantly reduces unnecessary data movement and memory footprint.
- **explicit layout transposition**：The kernel explicitly transposes matrix A (`aa = tl.trans(a)`) before the `tl.dot` operation. This optimization aligns the data layout in registers/SRAM with the specific operand ordering expected by the underlying hardware instruction, ensuring that the dot product can be executed without additional permutation overhead.

- `TritonPath`:

**坏实践（反例）**：分组 GEMM 静态均分任务（每核固定分到几个 block）→ 组间维度差异大时尾部效应明显，先完成的核闲置 → ✅ 正解即本条：while 循环动态取块（work stealing）+ `dot_pad_only_k` 只 pad 归约维、不整 tile padding。

**已知实例**：matmul §raw (`experiences/matmul/exp_grouped_gemm_001.yaml`)
- 声称性能收益：35%
- 备注：This kernel relies on the `dl` (DeepLink) module, indicating it is specifically designed for Ascend hardware (910 series). The dynamic scheduling is particularly effective when the variance in K dimensions across groups is high.
