## 禁止用 tl.where 动态计算内存偏移，改 if-else 静态分支

【优化维度】：编译器约束/hints
【适用条件】：平台 910b2/910b3 ｜ triton-ascend 版本 未标注（按验证版本）｜ dtype 全部 ｜ shape 任意（nd）
【泛化层级】：条件性（迁移条件：硬件 910b2, 910b3；失效边界：tl.where 用于数值选择（非指针/偏移计算）不受此约束；与 exp_api_002 互补——那张处理嵌套数值条件，本卡专治偏移计算；仅 910b2/910b3 验证，910C/310P 未验证（unverified)）

### 原则
- **核心避坑**：Ascend后端禁止使用`tl.where`动态计算内存偏移，该场景下硬件支持不完全，易触发执行错误
- **替代方案**：复杂条件的内存偏移计算，改用if-else静态分支处理，提前确定偏移值
- **适配逻辑**：静态分支可被Triton编译器优化为硬件友好的指令，避免动态偏移的兼容性问题

### 代码/骨架出处
- `Triton`:
```python
# ========== Ascend后端内存偏移计算避坑 ==========
@triton.jit
def offset_calc_kernel(input_ptr, output_ptr, n_elements, blockSize: tl.constexpr):
    pid = tl.program_id(0)
    base_offset = pid * blockSize
    
    # 错误: tl.where动态计算内存偏移（Ascend不兼容）
    # offsets = tl.where(base_offset < n_elements, base_offset + tl.arange(0, blockSize), 0)
    
    # 正确: if-else静态分支处理
    offsets = base_offset + tl.arange(0, blockSize)
    if base_offset < n_elements:
        mask = offsets < n_elements
        data = tl.load(input_ptr + offsets, mask=mask)
        tl.store(output_ptr + offsets, data * 2, mask=mask)
    # 超出范围的分支无需处理（天然跳过）
```

**坏实践（反例）**：Ascend后端对`tl.where`生成的动态指针运算存在底层指令支持缺陷，易导致kernel执行崩溃

**已知实例**：general_ascend §raw (`experiences/general_ascend/exp_ascend_where_001.yaml`)
- 声称性能收益：0%
- 备注：Ascend后端对`tl.where`生成的动态指针运算存在底层指令支持缺陷，易导致kernel执行崩溃；静态if-else分支是唯一安全的替代方案
