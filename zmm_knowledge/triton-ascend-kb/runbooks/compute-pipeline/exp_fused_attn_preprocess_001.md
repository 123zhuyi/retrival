## Scheduling Optimization: operator fusion

【优化维度】：多核并行与负载均衡
【泛化层级】：条件性（迁移条件：硬件 910b2, 910b3；失效边界：依赖 `dl.async_task` 扩展与 Cube/Vector 异构单元，无该 dialect 的环境不可用；k < 64 时 Cube 单元喂不饱；中间结果若需被其他 kernel 复用则不可融合）

### 原则
- **operator fusion**：Fuses the Value projection matrix multiplication (MatMul), Key RMS Normalization, and Query/Key Rotary Positional Embedding into a single kernel. This eliminates the need to write intermediate results to High Bandwidth Memory (HBM) and read them back for subsequent operations, significantly reducing memory access latency.
- **hardware pipeline scheduling**：Utilizes `dl.async_task` to explicitly dispatch the heavy compute load (MatMul) to the 'cube' unit and the light element-wise/reduction loads (Norm, Rotary) to the 'vector' unit. This allows for potential overlap of computation and memory transfers or efficient utilization of distinct hardware pipelines within the NPU.
- **memory access optimization**：By keeping the data within the on-chip memory hierarchy (L0/L1 buffers) across the three stages (MatMul -> Norm -> Rotary), the kernel maximizes data reuse and minimizes off-chip traffic, which is the primary bottleneck in transformer inference.

**坏实践（反例）**：投影 MatMul、归一化、位置编码各起一个 kernel → 中间张量在 HBM 两写两读，预处理阶段带宽翻倍 → ✅ 正解即本条：三阶段单 kernel 融合 + MatMul 派 cube、归一化/位置编码派 vector 的 async 分工。

**已知实例**：attention §raw (`experiences/attention/exp_fused_attn_preprocess_001.yaml`)
- 声称性能收益：35%
- 备注：This kernel is specifically designed for NPU architectures (like Ascend 910B) that support distinct Cube and Vector units. The `dl` module calls indicate hardware-specific dialect extensions for asynchronous task management.
