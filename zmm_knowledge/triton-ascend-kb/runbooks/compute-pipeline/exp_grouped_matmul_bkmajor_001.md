## Scheduling Optimization: dynamic load balancing

【优化维度】：多核并行与负载均衡
【泛化层级】：条件性（迁移条件：硬件 910b2, 910b3；失效边界：B 矩阵必须是 K-major 布局（或预格式化为该布局），否则显式转置假设不成立；组间维度均匀时动态分配无收益；`dot_pad_only_k` 依赖 CANN/Triton 集成）

### 原则
- **dynamic load balancing**：Implements a dynamic work distribution strategy within the kernel loop to handle variable matrix sizes in grouped operations. By calculating cumulative block counts (`cur_count`) and iterating with a stride equal to `total_cores`, the kernel ensures that all processing units remain active even when individual groups have uneven dimensions, significantly reducing core idle time.
- **hardware specific padding**：Utilizes `tl.compile_hint(..., "dot_pad_only_k")` for both input tensors. This instructs the compiler to apply padding exclusively along the K-dimension for the dot product operation. This is critical for NPU hardware (like Ascend) to align with the Cube unit's data requirements without the overhead of padding the M and N dimensions, thereby improving memory bandwidth utilization.
- **k major layout optimization**：The kernel is specifically designed for Matrix B in K-major (Column-major) format. It loads data from B using `strideBN` and `strideBK` and performs an explicit `tl.trans(b)` before accumulation. This allows the memory load unit to read contiguous segments along the K dimension (maximizing burst efficiency) while presenting the transposed layout required by the compute unit for the matrix multiplication.

### 代码/骨架出处
- `TritonPath`:
```python
raw_experiences/extracted_kernels/240-_m_grouped_matmul_bKmajor_kernel.py
```

**坏实践（反例）**：按组静态切分任务、不支持变长组 → 组维度不均时核大量闲置；对 K-major 的 B 不做片上转置直接 dot → layout 不匹配导致额外数据重排 → ✅ 正解即本条：累计 block 计数 + `total_cores` 步长的动态分配 + `tl.trans(b)` 片上转置。

**已知实例**：matmul §raw (`experiences/matmul/exp_grouped_matmul_bkmajor_001.yaml`)
- 声称性能收益：35%
- 备注：This kernel is optimized for scenarios where Matrix B is shared or pre-formatted in K-major layout. The 'dot_pad_only_k' hint is specific to the CANN/Triton integration for Ascend hardware.
