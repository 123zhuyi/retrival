## 语义速览（Compute 反推，fused_bias_leaky_relu.h:146-175）

```
t = x + bias                      (fp32：fp16 路径先 Cast 提升，CAST_NONE 精确)
u = LeakyRelu(t, negative_slope)  = t≥0 ? t : t·negative_slope   (fp32)
y = u · scale                                                    (fp32，fp16 路径 Cast RTNE 回 fp16)
```

- 分段边界差异无害：proto 注释写 `x+bias>0` / README 写 `≥0`——t=0 时两分支都得 0，语义等价。
- 两个 float 属性（negative_slope/scale）经 tilingdata 透传 kernel（host L196-197 → kernel L93-94），kernel 侧是 **runtime 标量**而非编译期常量。
- 全程无广播：bias 与 x 完全等形，整体打平为一维连续 elementwise。

## 缺省项与注意点（P1 必须处理）

1. **无 benchmark 语义超集问题**：benchmark 库未收录本算子，验收标杆须自建（torch 组合式 `torch.where(x+bias>=0, x+bias, (x+bias)*ns) * scale`，fp32 计算后回 cast）；卡片 §9 记录标杆形态与判定准则。
2. **proto 与 def 的 dtype 不一致**：proto 声明 {fp32, fp16, double}，def.cpp 与 kernel 仅 {fp16, fp32}——以 def.cpp 为准，P1 标偏差。
3. **README 产品支持表 vs def.cpp**：README 列 A2/A3/推理系列均 √，def.cpp 仅注册 ascend950 config——以 def.cpp 为准。
4. **BUFFER_MODE 模板语义**：tilingkey BUFFER_MODE∈{0,1}，kernel `BUFFER_NUM = BUFFER_MODE ? 2 : 1`（h:39）——0=单缓冲、1=双缓冲；空 tensor 时 host 强制 tilingkey=0。
5. 无 workspace（WS_SYS_SIZE=0），无多 kernel 分解，无 aclnn 参数消化层——add 卡的「勿复刻分解」清单本算子不适用（无分解可复刻）。
