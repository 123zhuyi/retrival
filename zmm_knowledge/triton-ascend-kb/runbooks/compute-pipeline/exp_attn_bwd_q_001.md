## Compute Optimization: mixed precision compute

【优化维度】：AICore 单元利用/Scalar 削减
【泛化层级】：条件性（迁移条件：硬件 910b2, 910b3, 91093, 91095；失效边界：BLOCK_C 未按目标硬件 L1/L2 容量调优时分块收益下降；S < BLOCK_C 时无需分块，单块直接计算更优；对精度不敏感的纯推理场景可全程低精度，fp32 中间路径反而增加开销）

### 原则
- **mixed precision compute**：The kernel strategically uses mixed precision by performing the softmax and intermediate gradient logic in HIGH_TYPE (typically float32) to preserve numerical stability during exponentiation. Crucially, the final gradient accumulation `tl.dot(block_ds.to(LOW_TYPE), block_k)` casts the data to LOW_TYPE (fp16/bf16) before the matrix multiplication. This leverages the high throughput of low-precision hardware matrix units (like Tensor Cores or Cube units) for the heavy GEMM workload while maintaining accuracy in the reduction path.
- **sequence chunking tiling**：The kernel processes the sequence dimension S in tiles defined by BLOCK_C. By loading tiles of inputB and inputC into shared memory (or cache) and reusing them for the computation of `block_dq`, the kernel significantly reduces global memory access frequency and improves data locality.
- **gradient accumulation pattern**：The operation `block_dq += ...` indicates that this kernel is designed to be invoked within a loop over the sequence chunks. This allows for efficient accumulation of gradients in registers or fast local memory, minimizing the overhead of writing partial results back to global memory until the final reduction is complete.

**坏实践（反例）**：整条反向链路（含 softmax 与指数运算）都在 fp16/bf16 下计算 → exp 上溢与累加误差导致梯度数值不稳定甚至 NaN → ✅ 正解即本条：softmax 与中间梯度用 fp32（HIGH_TYPE），仅在喂给矩阵乘单元前 downcast 到 fp16/bf16。

**已知实例**：attention §raw (`experiences/attention/exp_attn_bwd_q_001.yaml`)
- 声称性能收益：35%
- 备注：This kernel is a micro-kernel for the backward pass of an attention-like operator (计算对输入的梯度). It is optimized for scenarios where the sequence length S is large, requiring tiling. Ensure BLOCK_C is tuned to the specific hardware's L1/L2 cache size for optimal performance.
