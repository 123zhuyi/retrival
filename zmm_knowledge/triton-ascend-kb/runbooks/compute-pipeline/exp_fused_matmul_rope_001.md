## Scheduling Optimization: operator fusion

【优化维度】：多核并行与负载均衡
【泛化层级】：条件性（迁移条件：硬件 910b2, 910b3；失效边界：依赖支持硬件级任务拆分的 runtime（dl dialect）；位置编码的 cos/sin 若每次迭代重复计算会抵消融合收益；中间数据需能驻留 L0/L1，head_dim 过大时片上驻留失败）

### 原则
- **operator fusion**：Fuses the Rotary Position Embedding (RoPE) operation with the Matrix Multiplication (MatMul) into a single kernel launch. This eliminates the need to write the intermediate inputA tensor back to High Bandwidth Memory (HBM) after applying RoPE, significantly reducing memory bandwidth consumption and latency.
- **hardware unit scheduling**：Utilizes `dl.async_task` with specific scopes (`vector` for RoPE, `cube` for MatMul) to explicitly map computations to the appropriate processing units on the Ascend Da Vinci architecture. This allows for efficient pipelining where the Vector unit handles the trigonometric calculations while the Cube unit handles the matrix accumulation.
- **data locality optimization**：By keeping the data within the on-chip memory hierarchy (L1/L0 buffers) between the RoPE and MatMul stages, the kernel maximizes data reuse. The output of the vector calculation is directly fed into the cube unit without global memory synchronization.
- **operator fusion**：Fuses the Rotary Position Embedding (RoPE) element-wise operations with the Matrix Multiplication (MatMul) into a single kernel launch. This eliminates the need to write intermediate inputA and inputB embeddings to global memory (HBM) and read them back for the MatMul operation, significantly reducing memory traffic.
- **hardware unit pipelining**：Utilizes `dl.async_task` to explicitly dispatch the RoPE computation to the Vector unit (`scope=vector`) and the MatMul computation to the Cube unit (`scope=cube`). This allows the hardware to schedule these tasks on different physical execution units, potentially overlapping computation and hiding latency.
- **memory access optimization**：By fusing the operations, the data path is shortened. The rotated embeddings can be consumed directly by the matrix multiplication units or kept in higher-level cache (L1/L0 buffer), minimizing the bandwidth pressure on the external memory interface.

**坏实践（反例）**：位置编码后的中间张量写回 HBM 再读回做 matmul → 额外一次完整往返，vector 与 cube 串行空转 → ✅ 正解即本条：RoPE 派 vector、MatMul 派 cube，融合后中间结果片上直供。

**已知实例**：matmul §raw (`experiences/matmul/exp_fused_matmul_rope_001.yaml`)
- 声称性能收益：25%
- 备注：This pattern is specifically designed for Transformer-style architectures where RoPE is a prerequisite for the attention mechanism. The `dl.async_task` API implies a dependency on a specific runtime environment (likely Ascend/CANN) that supports hardware-level task disaggregation.
