## Scheduling Optimization: micro tiling strategy

【优化维度】：多核并行与负载均衡
【泛化层级】：条件性（迁移条件：硬件 910b2, 910b3；失效边界：仅适用 M/N/K ≤ 64 的小矩阵，大矩阵用 16x16x16 无法吃饱带宽与算力（备注自述）；allow_tf32=False 是用吞吐换精度，精度不敏感场景可放开；num_stages=3 的浅流水对更大 tile 不够用）

### 原则
- **micro tiling strategy**：Adopts a 16x16x16 tile size (blockM, blockN, blockK). This configuration is specifically optimized for small-scale matrix dimensions where larger tiles would lead to under-utilization of compute units or excessive boundary masking overhead.
- **precision control**：Enforces high-precision accumulation by disabling reduced-precision modes (allow_tf32=False). This ensures numerical stability and IEEE 754 compliance for the accumulator, which is critical for sensitive workloads despite the potential performance trade-off.
- **lightweight pipelining**：Utilizes a shallow 3-stage software pipeline (num_stages=3). Given the small memory footprint of the 16x16 tiles, a deeper pipeline is unnecessary and would increase register pressure; this configuration effectively hides memory latency without spilling.

### 代码/骨架出处
- `TritonPath`:
```python
raw_experiences/extracted_kernels/056-_tensor_matmul_kernel.py
```

**坏实践（反例）**：≤64 的小矩阵套用 128/256 大 tile → tile 大部分元素被 mask 掉，边界处理开销超过有效计算，算力利用率极低 → ✅ 正解即本条：16x16x16 微 tile + 3 级浅流水 + 严格精度累加。

**已知实例**：matmul §raw (`experiences/matmul/exp_matmul_small_tile_001.yaml`)
- 声称性能收益：15%
- 备注：This configuration is tailored for small matrix sizes (M,N,K <= 64). For larger matrices, this tile size is suboptimal as it cannot saturate memory bandwidth or compute throughput; larger block sizes (e.g., 128 or 256) are recommended.
