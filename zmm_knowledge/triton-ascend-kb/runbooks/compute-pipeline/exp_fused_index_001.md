## Compute Optimization: operator fusion

【优化维度】：AICore 单元利用/Scalar 削减
【泛化层级】：条件性（迁移条件：硬件 910b2, 910b3；失效边界：假设 inputA（H×K）足够小可驻留寄存器/cache 复用，H×K 大时假设失效；fp8 输入需硬件与指令支持；BLOCK_SIZE_N 的 autotune 空间（128/256/512）需按目标 shape 复核）

### 原则
- **operator fusion**：The kernel fuses four distinct operations — Matrix Multiplication (GEMM), ReLU activation, Scaling, and Reduction (Sum) — into a single kernel launch. This drastically reduces global memory read/write traffic by keeping intermediate results in high-speed registers or SRAM.
- **data reuse optimization**：The inputA matrix (shape HxK) and its corresponding scaling factors are loaded into registers once before the loop over the N dimension. This ensures that the inputA data is reused for every block of inputB loaded, minimizing memory bandwidth requirements for the inputA tensor.
- **auto tiling strategy**：Utilizes `@triton.autotune` to dynamically select the optimal `BLOCK_SIZE_N` (128, 256, or 512) based on the specific runtime dimensions of H, N, and inputB. This ensures the kernel achieves the best balance between occupancy and memory coalescing for varying sequence lengths.
- **boundary handling**：Implements mask-based loading and storing (`mask=...`) to efficiently handle sequence lengths (N) that are not perfectly divisible by the block size, avoiding expensive conditional branching within the kernel body.

**坏实践（反例）**：GEMM、ReLU、缩放、sum 归约拆成四个 kernel → 每个中间结果都落 HBM 再读回 → ✅ 正解即本条：单 kernel 融合四操作，inputA 在 N 维循环外一次加载寄存器复用。

**已知实例**：misc §raw (`experiences/misc/exp_fused_index_001.yaml`)
- 声称性能收益：45%
- 备注：This kernel is specifically optimized for index calculation or similarity search tasks involving FP8 quantization. It assumes the inputA matrix is small enough to fit in registers/cache for reuse across the N dimension.
